Meet the cast

Seven small files, each with one job. Knowing who does what lets you tell an AI tool exactly where a change belongs.

A small research lab

Think of the project as a lab with a front desk, a surveyor, a breeder and an illustrator. Nobody does anyone else's job. Each module below is one of those people.

main.py The front desk. Reads your command and starts everything.
src/ The lab itself
utils.py The surveyor. Reads map files and measures distances.
initialization.py The scout. Builds the first 100 routes.
operators.py The toolkit. Pick a parent, mix two routes, tweak a route.
ga.py The breeder. Runs the generation-after-generation loop.
experiments.py The lab manager. Repeats runs with different settings and writes the results down.
plot.py The illustrator. Turns numbers into charts.
data/ Map files, one per set of cities
results/ Charts and result tables the program produces
tests/ Small programs that check the other code still behaves

How one file borrows from another

The very top of ga.py shows who the breeder relies on. An import is a file reaching into another file's toolbox.

CODE 
from src.operators import (
    tournament_selection,
    order_crossover,
    swap_mutation,
    inversion_mutation,
)
PLAIN ENGLISH

From the toolkit file, bring in four tools:

the one that picks a parent,

the one that mixes two routes into a child,

a tweak that swaps two cities,

and a tweak that reverses a stretch of the route.

That is the complete list. The breeder imports nothing about files, maps or charts.

💡
Separation of concerns

Engineers call this "separation of concerns": each file knows about one thing. The benefit is practical. A change to the charts cannot break the algorithm, because the algorithm never touches the chart code.

One small tool, read line by line

Maps come with different rules for measuring distance. This short function in utils.py picks the right rule. A function that only decides who should handle a job is called a dispatcher.

CODE 
def pairwise(city1, city2, weight_type="EUC_2D"):
    """Dispatch to the TSPLIB edge-weight function for weight_type."""
    if weight_type == "GEO":
        return geo_distance(city1, city2)
    return euc2d_rounded(city1, city2)
PLAIN ENGLISH

A tool named "pairwise". Give it two cities and the map's distance rule. If you do not say which rule, assume flat straight-line distance.

A one-line description for human readers.

If the map uses real latitude and longitude…

…measure along the curve of the Earth.

Otherwise measure a straight line and round it to a whole number.

EUC_2D Flat map, straight-line distance. Used by berlin52, kroA100 and kroA200.
GEO Globe coordinates, distance along the Earth's surface. Used by burma14.
